## 怎麼放上 GitHub Pages

1. 在 GitHub 建一個新的儲存庫，例如 `sticky-notes`，選 **Public**
2. 把這個資料夾裡的**所有內容**（`index.html`、`css/`、`js/`、`README.md`）上傳進去
   - 網頁版做法：儲存庫頁面 → `Add file` → `Upload files` → 把檔案拖進去 → `Commit changes`
   - **注意要保留資料夾結構**，`css` 和 `js` 兩個資料夾要在，不能把檔案全部攤平
3. 儲存庫 → `Settings` → 左邊 `Pages`
4. `Source` 選 `Deploy from a branch`，Branch 選 `main`、資料夾選 `/ (root)` → `Save`
5. 等一兩分鐘，頁面上方會出現網址，格式是 `https://你的帳號.github.io/sticky-notes/`

之後每次更新，就是把新檔案重新上傳覆蓋，幾秒鐘生效。

> **這個網址要記下來**，之後設定 Google Cloud Console 時要填進「已授權的 JavaScript 來源」。

### 也可以直接在本機測試

直接用檔案總管點兩下 `index.html` 就會開。程式碼刻意沒用 ES module，就是為了讓這種開法能運作。
差別只有一個：`file://` 不是安全內容環境，剪貼簿可能會走舊版備援路徑，行為跟正式網址上略有不同。**要驗證複製功能請以 GitHub Pages 上的網址為準。**

## 操作方式

### 常用語（主要工作區）

- **點整列任何位置** → 複製內容到剪貼簿，切到客服系統按 Ctrl+V
- **按複製鍵** → 每一條可自訂一個鍵（0～9、A～Z，可搭配 Alt），按下去直接複製那一條
- **編輯只能點右側的 ✎ 鉛筆**，會開彈窗改標籤與內容。刻意不做點文字就編輯，那會跟「點一下複製」搶同一塊區域
- 內容超過兩行會出現 `▾`，點了展開完整內容
- **拖曳每列最左邊的 ⠿ 把手可以調整順序**，常用的可以拉到最上面。只有把手能起拖，不會跟點擊複製打架
- 常用語卡片**橫跨整行寬度**，標籤欄固定寬、內容欄吃掉剩下的空間

### 複製鍵

在 ✎ 編輯彈窗裡設定，按「設定」然後直接按下想用的鍵就錄起來，不用自己打字。

- 可用範圍：`0`～`9`、`A`～`Z`，可搭配 Alt（例如 `Alt+A`）
- **留空代表不設**，那一條就只能用滑鼠點
- 同一分類內不可重複，錄製當下就會擋下並告訴你是哪一條佔用了
- 不分大小寫；不支援 Ctrl 和 Win 組合，那些多半已被瀏覽器占用
- **純字元的鍵在打字時不生效**（不然搜尋框沒辦法用），Alt 組合則不受影響

> 衝突範圍限在同一分類，不是全軟體——複製鍵只對畫面上看得到的卡片有意義，全軟體唯一的話鍵很快就不夠分。一個分類最多可以有 36 個。

### 卡片排序與釘選

- **拖曳卡片左上角的 ⠿ 把手**可以調整順序。只有把手能起拖，避免選字或點常用語時誤觸
- **☆ 釘選**：釘起來的卡片固定排在該分類最前面，左側會多一條紫色邊
- 上限是**同一分類、同一類型最多三個**。便籤釘滿不會吃掉常用語的額度，各類型分開算

### 連結收藏（批次開啟）

- 每一列前面有勾選框，上方有**全選／取消全選**，右邊是**開啟已勾選（N）**
- **一個項目可以放多條網址**（編輯彈窗裡一行一條），開啟時**隨機挑一條**。被封鎖不會自動換下一條
- 只填一條就是一般連結，行為跟以前一樣
- **單獨點名稱**照樣只開那一個，不受勾選狀態影響
- 勾選狀態不會存檔，只是「這次要開哪幾個」的暫時選擇

> **一次開多個分頁需要先讓瀏覽器放行。** Chrome 預設只允許開第一個，其餘當成彈出式視窗擋掉。
>
> 被擋下時的完整說明**只會跳第一次**，之後只用一行小提示帶過。想再看說明，點連結卡片標題列上的圓形 **?** 鈕。
>
> 但這個設定是綁網址的，**用檔案總管直接開的 `file://` 可能存不住，這個功能請在 GitHub Pages 上使用。**

### 私人卡片（加密）

用來存需要保護的內容。**跟其他卡片不同，這張卡片的內容是真的加密過的**——存在瀏覽器裡的是密文，按 F12 也只看得到亂碼。

- **建議在 https 網址下使用。** 用檔案總管直接開的 `file://` 其實也能用（Chrome 把本機檔案視為安全環境，加密功能是在的），但正式使用請以 GitHub Pages 網址為準，那裡才存得住彈出視窗白名單、之後也才接得上 Drive 同步
- 萬一真的碰到不支援的環境（某些瀏覽器的 `http://` 頁面），卡片會顯示說明並停用，不會假裝有加密
- **新增時要先選「加密」或「不加密」**，沒有預設值。不加密的卡片內容是明文，任何能打開這個瀏覽器的人都看得到；標題列的圖示可以隨時互轉
- **每張加密卡片各自解鎖。** 輸入哪張卡片的密碼就只開哪張，其他張仍然隱藏著
- 第一次建立加密卡片時設定**主密碼**（長度不限，不只數字），系統會產生一組**復原金鑰**。之後新增的加密卡片沿用同一組主密碼，不會再產生新的復原金鑰
- **復原金鑰只出現一次**，忘記主密碼時是唯一的救援方式。請存在這個工具以外的地方
- 兩個都遺失就真的解不開了，只能全部刪除重來。這是加密的性質，不是設計限制
- 解鎖後**固定 10 分鐘自動隱藏**，計時不會因為操作而延長。標題列的 ⦿ 可以立刻隱藏
- **每一筆預設是摺疊的，只露出名稱**，左邊的 ▸ 點了才展開。這是多一層保護：路過的人瞄一眼只看得到你自己取的名字
- 摺疊狀態**不會被記住**。每次重新輸入主密碼進來，一律是全部摺疊，不會出現「上次展開的那筆還開著」
- 每一筆分兩種型別，新增時在彈窗最上面選：
  - **資訊**：名稱、網址、帳號、密碼、備註。帳號密碼各有複製鈕，密碼預設遮起來
  - **備忘錄**：名稱、網址、一整塊內容，展開後右下角有複製鈕
- **卡片上不標型別。** 兩種展開後長得不一樣，一眼就分得出來；標了反而等於幫人分類
- 有填網址的那一筆，名稱右邊會出現鏈條圖示，點了開新分頁
- **鎖住時不參與搜尋**，避免「搜得到就代表存在」洩漏資訊
- 有私人卡片時，**匯出資料前要先輸入主密碼**（匯出檔裡是密文）
- **刪除私人卡片、或刪除裡面的任何一筆，都要先輸入主密碼**（復原金鑰也可以），驗過了才會跳確認彈窗。驗證只是確認身分，不會把鎖著的卡片打開

標題列的小圓標預設寫「私人」，**點一下可以改成任何字**。這個標籤只是外觀、不是機密，所以鎖著也能改——用意是不讓卡片本身太顯眼。

### 彈窗的關閉方式

**編輯類彈窗只能用「取消」或「儲存」關閉。** 點背景、按 Esc 都不會關，避免打到一半誤觸就整批消失。

適用於：編輯常用語、編輯連結、新增／改名分類、新增卡片標題。

唯讀類彈窗（關於、分類選項、刪除確認、卡片類型選擇）按 Esc 仍可關閉，那些沒有會遺失的內容。

> 卡片標題、便籤、待辦的**就地編輯**不受影響——那些點到別處是**存檔**，不是丟棄。

### 其他

- 便籤、待辦：沒有複製行為，所以維持**點文字就能改**。便籤的編輯框**拉大之後會記住**，下次點進去就是那個大小
- 倒數提醒：日期顯示為「2026年9月30日（週三）」，三天內轉琥珀色、過期轉紅色。**點日期欄位任何位置都會跳出日曆**，底下可以加子任務清單
- 多行內容：**Ctrl+Enter 存檔**，直接按 Enter 是換行
- 分類貼紙可以**拖曳排序**，滑鼠移上去會出現 `⋯` 開選項
- **所有 ✕ 刪除都會跳確認視窗**：卡片、常用語、待辦項目、連結，一個都不例外

### 數字鍵的範圍

只綁**目前分類裡第一張常用語卡片**的前九條。同一個分類放兩張常用語卡片時，按 `1` 該複製哪一張的第一條講不清楚，所以只認第一張。第十條以後序號顯示 `·`，只能用滑鼠點。

## 重要提醒：這個階段請養成匯出留底的習慣

資料現在只存在**這台電腦的瀏覽器**裡。還沒接上 Google Drive，所以：

- 換電腦資料不會跟著走
- 影子系統還原之後，瀏覽器設定檔被清掉，資料就沒了
- 清除瀏覽器資料也會一併清掉

**每天結束前用 ☰ → 匯出資料存一份**，接上 Drive 同步之後就不用了。

## 資料格式

內部格式是 camelCase，最外層長這樣：

```json
{
  "version": 2,
  "updatedAt": "ISO 時間",
  "appTitle": "便籤／常用語",
  "settings": { "autoLockEnabled": false, "autoLockMinutes": 30 },
  "categories": [ { "id": "", "name": "", "shortLabel": "", "order": 0 } ],
  "tabs": [ { "id": "", "categoryId": "", "type": "quickphrase", "title": "", "order": 0, "rows": [] } ]
}
```

### 匯入相容性

匯入時會自動辨識三種格式：

1. **本版格式**（camelCase）
2. **桌面版 WPF 實際存檔**（PascalCase、`Categories` / `Tabs`、`Tabs` 底下用 `type` 區分類型）
3. **v1.3 規格書第 9 章的草案格式**（camelCase，但 `quickPhrases` 獨立成陣列、用 `tabId` 掛回卡片）

> 格式 2 和 3 其實不一樣——舊規格書的草案跟桌面版實際實作對不上。兩種都吃進來，以防萬一。

匯入桌面版資料時，這些欄位會被丟掉（瀏覽器版沒有對應功能）：
`PickerHotkey`、`PinnedWindowTitle`、`PinnedWindowProcess`、`PanelOpacity`、
`Rows[].Hotkey`、`Categories[].IsQuickPhraseZone`、`Tabs[].Mode`

## 已知限制

- **剪貼簿一定會被覆蓋**。這是改用剪貼簿機制的必然代價，桌面版原本刻意避開這點，瀏覽器做不到
- **數字鍵不是全域熱鍵**，網頁沒有焦點時無效。這是瀏覽器沙盒的硬限制
- **沒有刪除密碼保護**。桌面版規格裡的 4 位數密碼 + 安全問題還沒做，目前刪除只有一層確認彈窗
- **釘選的卡片永遠在最前面**，所以把已釘選的卡片拖到未釘選的區域，它只會停在釘選區的最後一個位置，不會真的跑下去
- 釘選目前只做**置頂排序**。之後的置頂小視窗（PiP）要不要沿用這個標記，等小視窗做出來看實際效果再決定
- **批次開啟的分頁沒辦法自動分組**。Chrome 的分頁群組只有擴充功能能操作，一般網頁碰不到
- **搜尋不做簡繁互轉**，打簡體找不到繁體內容，反之亦然
- **localStorage 沒有加密**，不需要登入就能讀。這是已知並接受的取捨，對應措施（登出清空、閒置鎖定）排在第 4 項
